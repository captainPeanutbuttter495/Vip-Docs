# Events API

Staff CRUD API for events: create, list, retrieve, partially update, and soft or hard delete. Mounted at `/api/v1/staff/`.

---

## Overview

This is the first real resource in `vip-web-backend`. It is built from DRF generic views over a single `Event` model. Every error uses the [[Error_Envelope]]. There is **no authentication, pagination, or CORS yet**. Auth on write routes is a known follow-up, and the frontend's server-side fetch doesn't need CORS.

---

## Data Model — `Event`

`events/models.py`. Default ordering is `-created_at`.

| Field | Type | Notes |
|-------|------|-------|
| `id` | UUID (PK) | `uuid4`, not editable |
| `title` | CharField(200) | Required |
| `slug` | SlugField(220), unique | Optional on create. Auto-generated by `generate_unique_slug()` |
| `description` | TextField | Blank allowed, default `""` |
| `status` | `draft` · `published` · `archived` | Default `draft`. **Read-only** through the API |
| `event_type` | `workshop` · `webinar` · `conference` · `other` | Required |
| `category` | `general` · `challenge` · `community` | Default `general` |
| `start_datetime` | DateTime | Required. Stored in UTC (`TIME_ZONE = "UTC"`, `USE_TZ = True`) |
| `end_datetime` | DateTime, nullable | Must be ≥ `start_datetime` |
| `created_at` / `updated_at` | DateTime | Auto |
| `deleted_at` | DateTime, nullable | Soft-delete marker. **Not serialized** |

### Slug generation

`slugify(title)[:200] or "event"`, then `-2`, `-3`, … until the slug is unique. The base is capped at 200 characters so the suffix still fits within 220.

## Endpoints

| Method | Path | View | Result |
|--------|------|------|--------|
| GET | `/api/v1/staff/events` | `EventListCreateView` | 200, plain JSON array of live events (no pagination) |
| POST | `/api/v1/staff/events` | `EventListCreateView` | 201 created event · 400 `validation_error` |
| GET | `/api/v1/staff/events/<uuid>` | `EventDetailView` | 200 · 404 `not_found` |
| PATCH | `/api/v1/staff/events/<uuid>` | `EventDetailView` | 200 · 400 · 404 |
| PUT | `/api/v1/staff/events/<uuid>` | — | **405**. Updates are deliberately PATCH-only |
| DELETE | `/api/v1/staff/events/<uuid>` | `EventDetailView` | 204 soft delete · `?permanent=true` → 204 hard delete · 404 |

Both views filter the queryset with `deleted_at__isnull=True`, so a soft-deleted event returns **404** on GET, PATCH, and DELETE.

### Delete semantics

`perform_destroy` checks `?permanent=` (case-insensitive):

- `true` → `instance.delete()` removes the row.
- anything else, or no parameter → `instance.soft_delete()` sets `deleted_at = now()`.

The `permanent` query parameter is documented in OpenAPI through `@extend_schema` on `delete()`, not `destroy()`, because drf-spectacular reads annotations from the HTTP handler.

## Validation — `EventSerializer`

- `id`, `status`, `created_at`, and `updated_at` are read-only. A client-supplied `status` is silently ignored on both create and PATCH.
- **Cross-field rule:** `end_datetime >= start_datetime`. On PATCH, a missing side falls back to the stored instance value, so the rule holds against the *merged* state.
  - Example: PATCHing only `end_datetime` to a time before the stored start → 400.
- A duplicate explicit `slug` returns 400 from the model's unique constraint, rendered as `validation_error`.

## Known Gaps vs. the Frontend Card

The frontend `EventItem` needs `location`, `organization`/host, `audience`, a registration URL, and a card-status chip. The backend has none of these. The two shapes also conflict:

- Backend `status` is a publishing state, while the frontend `status` is a registration badge.
- Backend `category` values don't overlap with the frontend's.

The proposed v2 model is in [[Events_API_Integration]]. The full gap table is in [[Events_Page]].

## Card Fields — `feature/events` (unmerged)

Everything above describes `origin/main @ 6b62343`. The `feature/events` branch (commits `bdb82f4` … `d2010b3`, 2026-09-29) closes most of the card gap.

| Field | Type / values | Rule |
|-------|---------------|------|
| `category` | `event` · `program` · `workshop` · `signature_event` | Required. Replaces `general` / `challenge` / `community` |
| `tag` | `open_registration` · `accepting_applications` · `limited_seats` · `flagship` · `on_campus` · `family_friendly` | Optional, default `""` |
| `format` | `in_person` · `online` · `hybrid` | Required |
| `location` | CharField(255) | Required for `in_person` and `hybrid` |
| `online_url` | URLField | Required for `online` and `hybrid` |
| `host` | CharField(200) | Required |
| `audience` | `students` · `community` · `educators` · `families` | Required |
| `url` | URLField | Optional registration link, default `""` |

- `event_type` is **removed**. The response contract is now 17 keys (`EVENT_KEYS` in the tests).
- **Format rule.** `REQUIRED_BY_FORMAT` in `events/serializers.py` maps each format to the fields it requires. `validate()` checks it against the merged state, like the date rule, so a PATCH that changes only `format` is still validated. All field errors are collected into one 400.
- **Migration `0003_event_card_fields`:**
  - A `RunPython` step first maps the old categories to `event`.
  - It then removes `event_type` and adds the new columns.
  - Existing rows get one-off defaults (`format=in_person`, `host="TBD"`, `audience=community`) through `preserve_default=False`.
- The README (uncommitted) gains an Events API section and seed instructions. The Postman collection gains a "Sample events (one per category)" folder.
- Tests: `tests/test_events_fields.py`, 34 cases. See [[Testing]].
