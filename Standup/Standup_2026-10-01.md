## Summary

- **Decisions:**
  - **No auth for now.** POST, PATCH and DELETE stay manual ("everything manually, at least currently"). Bearer-token auth comes "in the near future." Pinned.
  - **Compatibility before the middleware.** The Events page must work from **static JSON in the frontend** (like the rest of the site today) *and* from the backend. That way it can go live before AWS is ready, since IT approvals for AWS services are slow. Collisions and duplicates are "not so much of an issue" because only the team enters data, but it should stay backward compatible.
  - **Ship it:** "Find a way we can populate it using the data, do a PR, so that we can actually have the events page already up and running."
  - **Deployment:** ECS Express is the leaning choice because it's easier and costs little at our scale. RDS for Postgres is confirmed ("no other way"). Docker images go to AWS (ECR).
  - Delete doesn't need rate limiting: "only gonna be a few events."

## Transcript / Notes

**Presentation (me):**
- Backend organization:
  - `backend/` is the Django project layer: settings, root URLs, health, entry points.
  - `events/` is the domain: URLs, views (CRUD), serializer validation, model.
  - `tests/`.
  - Runtime and tooling: Docker/Compose, and GitHub Actions CI (ruff, migration check, pytest).
- Ways to create events today: Swagger UI and curl (demoed a "Family Science Night" POST → 201). Validation means a missing required field never reaches the database (400).
- Request pipeline: `/api/v1/staff/` → events URLconf → list/create view → serializer validation → ORM save, or a 400 with the `{code, message, details}` envelope.
- Soft delete by default; `?permanent=true` hard-deletes. `/healthz/` returns 503 when the database is unreachable.
- Gaps: no auth, events entered by hand only.
- Questions asked:
  - Should staff routes require auth?
  - Should a public route return only published events?
  - Who creates events (Django admin, a CMS, or another workflow)?
  - What does production readiness need?
  - Local → AWS mapping: ECS/Express, RDS, ECR, Secrets Manager / Parameter Store, CloudWatch.
